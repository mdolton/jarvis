# Plan 1 Follow-ups (Tracked Debt)

Items surfaced by the end-of-Plan-1 code review that were deliberately deferred to Plan 2 (or later) rather than fixed inline. Each item has a clear home in a subsequent plan.

## From final end-to-end review

### Plan 2 (Agent core + MCP)

- **`bootstrap()` uses `Base.metadata.create_all` instead of Alembic.** Acceptable for Plan 1's test-only context; Plan 6 will wire Alembic into production boot. In the meantime, add a test in Plan 2+ asserting that `alembic upgrade head` on a fresh DB produces the same schema as `Base.metadata.create_all` — catches silent drift between the two paths before Plan 6.
- **`AuditLogger` batch loss on DB error is silent, unbounded, and unretried.** Plan 2 will be the first to actually emit audit traffic at scale (tool calls, LLM requests). Before Plan 2 wires up real emission, decide:
  - Add a `maxsize` to the queue (what happens when full — drop oldest, block, or raise?).
  - Add a drop counter exposed via a metric or simple attribute for the dashboard.
  - Add a 1-retry-on-DB-error pattern before discarding a batch.
- **`ConversationRepo.touch` is unused.** Plan 2's trigger dispatcher / `MessageRepo.append` should be calling it when a conversation receives new activity (to keep `last_activity_at` current). If not, delete it.
- **`ConversationRow.idle_timeout_sec` column is never read/written.** Plan 2's dispatcher should decide per-conversation overrides: `conversation.idle_timeout_sec or config.idle_timeout_sec`. If we're not going to use the column, drop it in Plan 2's migration.
- **`AuditRepo.recent` returns ORM rows, not `AuditEvent` Pydantic models.** Plan 5 (dashboard) will need JSON-serializable views. Either the repo maps to `AuditEvent` at the boundary, or the dashboard adds a view-model layer. Decide before Plan 5 starts building the audit log view.
- **`MCPToolRepo.replace_for_server` accepts `list[dict]`.** Define an `MCPToolDescriptor` Pydantic model in `core/types.py` before Plan 2's `MCPManager` starts feeding data in.
- **Missing composite index on `conversations(channel_kind, channel_ref, status)`.** The hot query in `find_or_create_open` does a triple-equality + order-by-limit. Add the index in Plan 2's first migration.
- **`MessageRepo.role` is free-form `str`.** Add a `MessageRole` `StrEnum` in `core/types.py` and tighten the type.

### Minor / nice-to-have (no plan yet)

- **`MCPServerRepo.upsert` on transport change doesn't reset `status` / `last_error`.** When Plan 2 exercises this, decide whether transport change should force a reconnection cycle.
- **`expand_env` regex only matches `[A-Z0-9_]`.** Either broaden to POSIX env-var naming (`[A-Za-z_][A-Za-z0-9_]*`) or explicitly reject unknown casing. Currently silent passthrough.
- **`Base.metadata.naming_convention` is unset.** Autogenerated index/constraint names will vary. Cheap to add and saves grief in Plan 6's first real migration.
- **`alembic/env.py`'s `fileConfig` call resets the root logger.** Pass `disable_existing_loggers=False` to keep pytest log capture intact.
- **Pydantic validation errors wrapped via `ConfigLoadError(str(e))` may echo malformed values** including secrets like API keys. Consider redacting specific field names before stringifying.
